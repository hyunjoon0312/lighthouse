# 변경에 따른 검증

완료 기준을 정할 때 읽는다. 기존 실측은 루트 `docs/verification.md`에 있으며 오늘의 변경을 자동으로 검증하지 않는다. 명령은 프로젝트 루트 기준이며 실행 도구와 실제 Xcode/Swift 환경을 확인한다.

## 반드시 유지할 경계

- 원본 사진은 읽기만 한다. 보정값과 폴더 정보는 별도 저장하고 JPEG·LUT 내보내기는 기존 파일을 덮어쓰지 않는다. 테스트 전후 원본 bytes의 SHA256을 비교한다.
- 카탈로그·폴더 로드 실패를 빈 데이터로 간주해 저장하지 않는다. 기존 카탈로그의 키 누락 기본값, 손상 타입 거부, 원자 저장을 함께 확인한다. 손상된 폴더와 개별 LUT가 다른 사진의 편집을 막거나 덮어쓰기를 일으키지 않아야 한다.
- 사진·참조·카탈로그는 로컬에 둔다. 테스트 사진을 외부 서비스에 업로드하지 않는다.
- 미리보기와 최종 JPEG는 같은 색 처리·마스크 의미를 사용한다. CI 작업 공간과 LUT sRGB 변환을 혼동하지 않는다. 회전·크롭 후에도 마스크가 같은 피사체를 가리키는지 확인한다.
- 비동기 결과는 원래 요청한 사진·편집 상태와 맞을 때만 반영한다. 선택 변경·취소·중복 요청·시트 종료 중 저장 상태를 검증한다.

## 최소 검사 선택

| 변경 | 관련 명령 / 확인 | 추가 검사가 필요한 조건 |
| --- | --- | --- |
| 공용 모델·카탈로그·기본 파이프라인 | `swift test --filter CoreTests` | 공용 Codable/렌더 경계 변경은 전체 `swift test`와 소비 앱 빌드 |
| LUT 파서·색 적용 | `swift test --filter LUTTests` | 색 공간·보간 변경은 생성 이미지 픽셀과 preview/export 비교 |
| LUT 저장·목록 | `swift test --filter LUTLibraryTests` | 파일 무결성·마이그레이션 변경은 손상 격리와 재로드 |
| 일괄 선택·히스토리 | `swift test --filter BatchEditingTests` | UI 연결 변경은 필터 전환·여러 장 선택·undo/redo·선택 JPEG |
| 참조 색감 | `swift test --filter ReferenceColorMatchTests` | 알고리즘 변경은 소스/참조·저장 재적용 오차 실측; 카메라 규격은 별도 |
| 폴더 저장 | `swift test --filter PhotoFolderTests` | 화면 변경은 생성·이름·추가/제거·선택 필터·재시작 복원 |
| SwiftUI·AppKit 연결 | `swift build` | 실제 `.app`의 클릭·키보드·시트·메뉴·실행 취소·재시작 확인 |
| 패키징 | `./scripts/build-app.sh`, `codesign --verify --deep --strict dist/Lighthouse.app` | 로컬 ad-hoc 서명과 배포 공증은 별개 |
| 하네스·역할·스킬 | `python3 .agents/skills/harness/scripts/validate.py --project .`, `python3 scripts/test-harness.py` | 실행 로직 변경은 실제 자식 ID·인계·독립 검토 관찰 |
| 짧은 안내 문구·링크 | diff·상대 링크·관련 구조 검토 | 앱 전체 테스트를 관성적으로 반복하지 않음 |

테스트 클래스와 커맨드가 바뀌면 실제 테스트 탐색으로 확인한다. 통과한 전체 스위트는 새 변경·실패·미해결 위험이 없으면 반복하지 않는다. 소비자가 아직 없을 때는 계약만 검토하고 실제 통합은 `not_run`으로 둔다.

## 이미지·화면·실기

`LIGHTHOUSE_DATA_DIR`에 실행마다 다른 임시 경로를 제공한다. QA 산출물은 `.artifacts/<run-id>/` 아래에 둔다. 실행 로그·원본 파일·카탈로그·만든 LUT는 기본 Git 제외 대상이다. 앱이 이미 사용자 카탈로그로 실행 중이면 먼저 상태를 확인하고 QA 인스턴스의 저장 경로를 보장한다.

실제 UI 검증에는 현재 이용 가능한 macOS 앱 조작 도구를 사용하고 해당 스킬·문서를 읽는다. 창을 가져올 수 없거나 권한·화면 상태 때문에 실패하면 오류를 남긴다. 빌드 성공, 프로세스 생존, 모델 테스트를 화면 조작 통과로 바꾸지 않는다. 무작정 기존 앱을 종료·재시작하지 않는다.

RW2는 지원 카메라 목록, 실제 파일 디코딩, 보정·JPEG 출력, 촬영 모드별 확인을 구분한다. 루트 `.artifacts/`에 과거 샘플이 있더라도 새 PC에 있다고 가정하지 않는다. 샘플 확보가 필요한 검사는 사유와 함께 미실행으로 기록하고 독립 검사는 계속한다.

S9용 LUT는 앱 파싱, 공식 규격 확인, LUMIX Lab/SD 전달, 실기 로딩, 실제 촬영을 구분한다. 카메라나 펌웨어·포토스타일에 대한 새로운 호환 주장은 Panasonic 공식 자료를 날짜와 함께 다시 확인한다. 현재 생성기는 33³ full-range `.cube`, `#LUMIXPHOTOSTYLE STD`를 사용한다. 맥 RAW 현상과 카메라 Standard의 색은 동일하다고 가정하지 않는다. 카메라 없이 실기 검사를 완료 처리하지 않는다.

## 결과와 재검증

각 검사는 `passed`, `failed`, `not_run`과 실제 근거·필수 여부를 가진다. 발견 사항에는 파일·행, 트리거, 기대/실제, 수정 범위와 영향을 적는다. 필수 실패·미실행이 남으면 해당 범위의 완료를 막고 사용자에게 분명히 알린다. 선택 검사를 생략한 이유도 기록한다. 수정 뒤에는 영향받은 생산자와 소비자를 재검증한다.
