# Lighthouse

macOS에서 사진을 정리하고 선별한 뒤 RAW를 보정해 JPEG로 내보내는 로컬 데스크톱 앱입니다. Panasonic LUMIX S9의 RW2를 주 대상으로 개발했습니다.

## 실행

현재 Mac에서는 `dist/Lighthouse.app`을 더블클릭해 실행하면 됩니다. **사진 가져오기**로 시작하세요. 외부 패키지나 계정은 필요하지 않습니다.

소스에서 빌드하려면 macOS 15 이상과 Swift 6을 포함한 Xcode 또는 Command Line Tools가 필요합니다.

```sh
./scripts/build-app.sh
open dist/Lighthouse.app
```

개발 중에는 `swift run Lighthouse`로 실행할 수 있습니다. `Package.swift`를 Xcode에서 열어 개발할 수도 있습니다. 현재 번들은 로컬 실행용 ad-hoc 서명을 사용하며 배포용 공증은 포함하지 않습니다.

## 사용 흐름

1. **사진 가져오기**에서 RW2·JPEG·HEIC·PNG·TIFF 파일이나 사진 폴더를 선택합니다. Finder에서 파일이나 폴더를 창으로 끌어 놓아도 됩니다. 하위 폴더도 탐색하며 같은 경로를 반복 가져오면 중복을 제외합니다. 메모리 카드는 **카드에서 복사…**(⇧⌘O)를 쓰세요. 원본은 카드에 두고 사진을 `~/Pictures/Lighthouse/연도/연-월-일`(위치 변경 가능)로 복사한 뒤 가져오므로 카드를 빼도 계속 편집할 수 있습니다. 같은 카드를 다시 가져오면 이미 복사한 사진은 건너뜁니다.
2. 그리드에서 사진을 고르고 별점과 선택·제외 표시를 붙입니다. 블로그용·인화용처럼 따로 구분하려면 6–9 키나 오른쪽 패널로 색상 라벨(빨강·노랑·초록·파랑·보라)을 붙이고, 조건 단추에서 라벨로 거릅니다. 위쪽의 **표시 후 다음 사진**을 켜면 키로 표시할 때마다 다음 사진으로 넘어갑니다. 위쪽 정렬 메뉴로 촬영 시각·파일 이름·별점 높은 순으로 볼 수 있고(같은 값끼리는 촬영 시각 순), 그리드에서는 선택 줄의 슬라이더로 썸네일 크기를 바꿉니다. 오른쪽 패널에서 키워드(쉼표로 구분)와 설명을 붙이면 검색으로 찾을 수 있고 JPEG로 내보낼 때 IPTC 키워드·설명으로 들어갑니다. 여러 장을 골랐으면 **선택한 N장에 키워드 추가**로 한 번에 붙입니다. 별점·표시처럼 ⌘Z로 되돌릴 수 있습니다. 사진 보기에서 사진을 클릭하면 그 위치를 100%로 확대하고, 다시 클릭하면 화면 맞춤으로 돌아옵니다. Y(또는 **전·후 나눠 보기**)를 누르면 한 장을 선으로 나눠 왼쪽은 보정 전(구도만 적용), 오른쪽은 보정 후로 보여 주며 선은 끌어 옮깁니다. 검색창 옆 **조건** 단추로 카메라·렌즈·초점거리·ISO·촬영일·표시를 걸어 거르고, 그 조건을 **스마트 폴더**로 저장하면 조건에 맞는 사진이 자동으로 모입니다. **원본 위치**별로 찾아보거나 **내 폴더**를 만들어 사진을 묶습니다. 그리드의 사진을 왼쪽 내 폴더로 끌어 넣을 수 있고, 선택한 사진 중 하나를 끌면 선택한 사진이 모두 들어갑니다. [폴더와 원본 보존](docs/photo-folders.md)을 참고하세요. RAW+JPEG로 찍은 사진은 위쪽 **RAW+JPEG 한 장으로**가 켜져 있으면 RAW만 보입니다(JPEG는 카탈로그에 남고 끄면 다시 보입니다). **연속 촬영**에서는 1초 이내에 이어 찍은 컷을 묶어 보고, 선명도와 얼굴 품질로 묶음마다 추천 컷을 고를 수 있습니다. 자세한 내용은 [연속 촬영 고르기](docs/bursts.md)에 있습니다.
3. 사진 보기에서 **자동**(⌘U)으로 노출·색온도·틴트·하이라이트·섀도의 출발점을 정한 뒤 손으로 다듬을 수 있습니다(색이 한쪽으로 치우친 노을·실내 조명 사진은 지나치게 중립으로 갈 수 있어 색 보정 폭을 제한합니다). 노출, 색온도·틴트, 대비, 하이라이트·섀도, 명료도, 생동감·채도, 선명도, 비네팅과 RGB 곡선·색상 범위·필름 입자를 조절합니다. RAW는 노이즈 감소·렌즈 보정·하이라이트 복구와 **HDR 하이라이트**(0–2)도 조절할 수 있습니다. HDR 하이라이트를 켜면 SDR 흰색을 넘는 밝은 부분이 HDR(XDR) 화면에서 더 밝게 보이고 중간 톤은 그대로이며, 노출을 올릴수록 효과가 커집니다. HDR을 표시하지 못하는 화면에서는 SDR로 보입니다. 슬라이더의 이름이나 값을 두 번 누르면 그 항목만 기본값(RAW 현상은 자동)으로 돌아갑니다. 자유 크롭과 수평 보정으로 구도를 정합니다. [고급 보정 안내](docs/advanced-editing.md)를 참고하세요.
4. **부분 보정**에서 피사체·배경을 자동 선택하거나, 브러시로 칠하거나, 직선·원형 그라데이션을 놓아 해당 부분의 노출·대비·색온도·채도·명료도를 조절합니다. 지우개, 경계 부드럽게, 여러 영역, 마스크 표시를 지원합니다. **복구**에서는 작은 잡티를 복구하거나 직접 고른 소스를 복제합니다.
5. 오른쪽 패널 **스냅숏 · 보정 기록**에서 지금 보정을 이름 붙여 저장해 두고 언제든 그 상태로 돌아갈 수 있습니다(카탈로그에 저장). 같은 곳의 보정 기록은 이번 실행에서 바꾼 순서를 보여 주며 누르면 그 상태로 돌아갑니다. 둘 다 ⌘Z로 되돌릴 수 있습니다. 같은 사진을 다르게 보정하려면 **가상 사본 만들기**(⌘')로 파일 복제 없이 보정만 따로 가진 사본을 만듭니다. **전체 보정 → 프리셋 → 현재 보정 저장…**으로 자주 쓰는 보정(전체 보정·LUT·구도 중 선택)을 이름 붙여 저장하고, 현재 사진이나 선택한 여러 장에 한 번에 적용합니다. **가져올 때 적용**을 정하면 새로 가져오는 사진에 자동으로 적용합니다.
6. **전체 보정 → LUT → .cube 추가…**로 여러 LUT를 보관하고 목록에서 골라 적용합니다. 강도는 0–100%로 조절합니다. [LUT 사용 안내](docs/lut.md)에서 형식과 백업 방법을 확인할 수 있습니다.
7. **참조 사진 색감 맞추기…**에서 원하는 사진의 톤·색 분포를 근사하고 결과를 적용하거나 새 LUT로 보관합니다. **S9용 .cube 내보내기…**로 카메라 지원 규격의 파일을 만들 수 있습니다. [참조 색감과 S9 안내](docs/reference-match.md)를 읽어주세요.
8. 체크 버튼·⌘클릭·⇧클릭으로 사진을 여러 장 선택한 뒤 **일괄 적용…**에서 보정 범위를 고릅니다. **선택한 N장에 LUT 적용**은 LUT만 복사합니다. [여러 사진 편집 안내](docs/batch-editing.md)에 자세한 동작을 설명했습니다.
9. 비슷한 컷 여러 장을 고를 때는 사진을 여러 장 선택하고 **여러 장 보기**(N)로 최대 12장을 한 화면에 크게 놓습니다. 칸을 누르면 그 사진에 별점·표시 키가 붙고 ←/→는 놓인 사진 사이만 옮기며, ×로 탈락시킨 컷을 빼 나갑니다. 비교 모드에서는 기준 사진과 다른 사진을 나란히 보며 선별합니다. 기준 사진은 보정한 모습으로 보여 가상 사본끼리도 비교할 수 있고, **기준 원본 보기**로 보정 전 모습으로 바꿀 수 있습니다. 화면 맞춤과 100% 보기를 전환할 수 있습니다.
10. **내보내기**에서 실제 저장 결과의 미리보기와 파일 크기를 확인하고 현재 사진, 선택한 사진 또는 현재 필터 결과를 저장합니다. 형식은 JPEG(8비트)·HEIF(10비트)·TIFF(압축하지 않은 16비트, 2400만 화소 약 140MB), 색 공간은 sRGB와 Display P3 중에서 고릅니다. P3는 RAW의 넓은 색을 남기지만 P3를 모르는 곳에서는 옅게 보일 수 있어 공유용은 sRGB가 안전합니다. 긴 변과 품질(JPEG·HEIF)을 선택할 수 있고 파일명이 겹치면 접미사를 붙입니다. 여러 장에서는 대표 사진 한 장의 크기를 표시하며, 진행 중에 **중지**하면 처리 중인 한 장까지만 저장합니다. 촬영일·카메라·렌즈·노출 정보는 원본에서 옮기며, 위치(GPS)는 **위치(GPS) 정보 포함**을 켠 경우에만 넣습니다. 저장 폴더는 다음에 열 때 기억합니다. 사진마다 마지막 내보내기(설정·폴더·이름)를 카탈로그에 기억해 두므로, 그 뒤 보정·키워드·설명을 바꾼 사진은 내보내기 창 맨 위(또는 **파일 › 바뀐 사진 다시 내보내기…**)에서 한 번에 다시 내보낼 수 있습니다. 이전 파일은 기본으로 그대로 두고 새 파일에 번호를 붙이며, 원하면 앱이 쓴 그대로일 때만 휴지통으로 옮기고 같은 이름으로 씁니다. 파일 이름은 `{원본}`·`{날짜}`·`{시간}`·`{번호}`·`{사본}`으로 규칙을 정하고(가상 사본은 `{사본}`이 없어도 `-사본1`이 붙습니다), 글자 워터마크(위치·크기·불투명도)를 넣을 수 있습니다. 자주 쓰는 설정은 **프리셋 → 현재 설정 저장…**으로 보관하며 블로그용(긴 변 2048px·85%)과 원본 크기(95%) 프리셋이 기본으로 있습니다.

## 사진과 보정값 저장

원본은 가져온 위치에 그대로 유지하고, 분류와 보정값은 `~/Library/Application Support/Lighthouse/catalog.json`에 자동 저장합니다. 원본을 이동하거나 외장 드라이브 연결을 해제하면 그 사진에 **원본 없음** 표시가 붙고 왼쪽에 **원본 없음** 목록이 생깁니다. 앱으로 돌아오거나 드라이브를 연결·해제할 때마다 다시 확인합니다. 파일을 옮겼다면 오른쪽 패널이나 **사진 → 위치 다시 찾기…**에서 파일이 지금 든 폴더(또는 그 상위 폴더)를 고르세요. 같은 옛 폴더 아래에서 없어진 다른 사진도 새 위치에 파일이 있으면 함께 다시 연결합니다. 원본 삭제와 이동은 앱에서 수행하지 않습니다.

다른 사진 앱과 별점·키워드를 나누려면 **사진 › 별점·키워드를 XMP 사이드카로 쓰기**를 켜세요. 켜 둔 동안 별점·제외(-1)·색상 라벨·키워드·설명을 원본 옆 `<파일 이름>.xmp`(Adobe 방식)에 쓰며 원본 파일은 바꾸지 않습니다. 가상 사본은 쓰지 않고, RAW+JPEG는 RAW 쪽 한 파일만 씁니다. 이미 있는 사이드카가 카메라·다른 앱이 만든 것이면 덮어쓰지 않고 알려 줍니다. 보정값은 사이드카에 넣지 않습니다(다른 앱과 보정 방식이 달라서). 기본은 꺼져 있으며, 켜면 사진 폴더에 파일이 생깁니다.

사진과 보정은 `catalog.json`, 내 폴더 구성은 같은 위치의 `folders.json`, 스마트 폴더는 `smart-folders.json`, LUT와 표시 이름은 `LUTs` 폴더, 자동 선택 마스크는 `Masks` 폴더, 보정 프리셋은 `presets.json`에 보관합니다. `Thumbnails` 폴더는 사진마다 최신 썸네일 한 장을 두는 캐시입니다(360px JPEG, 한 장에 수십 KB). 원본이 없거나 드라이브를 뺀 사진도 이 썸네일로 보이며, 지워도 다시 만들어집니다. 첫 버전은 개인 라이브러리를 대상으로 하며 수만 장의 대규모 처리 성능은 아직 검증하지 않았습니다. 백업할 때 이 파일·폴더들과 원본 사진을 함께 보관하세요. 앱은 하루에 한 번(그날 처음 열 때, 켜 둔 채 날짜가 바뀌면 그날 첫 저장 때) `Backups/YYYY-MM-DD` 폴더에 카탈로그·내 폴더·스마트 폴더·프리셋을 남기고 최근 7일치만 유지합니다. 자동 마스크는 날짜 폴더의 `Masks`에 함께 들어 있어 그 폴더만으로 되돌릴 수 있습니다. 바뀌지 않은 마스크는 원래 `Masks`의 파일을 하드 링크하므로 보관본이 여러 개여도 디스크를 한 벌만 씁니다. **파일 › 카탈로그 보관본 보기**로 폴더를 엽니다. 되돌리려면 앱을 끝낸 뒤 원하는 날짜 폴더 안의 파일과 `Masks` 폴더를 위 위치에 덮어 두세요. LUT와 원본 사진은 보관본에 들어가지 않습니다.

RAW 지원은 macOS의 카메라 지원에 따릅니다. 현재 개발 Mac에서 S9의 일반 24MP RW2를 실제 현상·내보내기로 확인했습니다. 모든 펌웨어·촬영 모드의 RW2를 확인한 것은 아닙니다. 내보내기는 SDR(JPEG·HEIF·TIFF, sRGB 또는 Display P3)이 기본이며, RAW에 **HDR 하이라이트**를 켠 사진은 JPEG·HEIF에 게인 맵을 넣은 HDR 파일로 저장합니다(TIFF는 SDR). 클라우드 동기화, 여러 장 HDR 병합, Lightroom 카탈로그 호환은 제공하지 않습니다. 자동 선택은 사진에 따라 실패하거나 수동 수정이 필요할 수 있습니다.

## 검증과 개발 자료

```sh
swift test
swift build
```

`LighthouseCoreTests`는 코어를, `LighthouseTests`는 실제 `LibraryModel`로 가져오기·보정·실행 취소·내보내기·연속 촬영·원본 없음 등 전체 흐름을 만든 사진으로 검사합니다. S9 RW2 표본이 있으면 RAW 부분(카메라 미리보기, 카드 복사, RAW+JPEG, 드래그 반응)도 검사하며, 없으면 그 검사는 건너뜁니다. 표본은 저장소 위쪽의 `.artifacts/samples/LUMIX-S9.RW2`에서 찾거나 경로를 지정합니다. 표본 파일은 읽기만 하고 테스트는 임시 폴더의 복사본을 씁니다.

```sh
LIGHTHOUSE_SAMPLE_RW2=/path/to/P1000123.RW2 LIGHTHOUSE_SAMPLE_FACES=/path/to/faces swift test
```

`.github/workflows/ci.yml`은 푸시·풀 리퀘스트마다 macOS 26 러너에서 빌드와 테스트를 돌리도록 적어 두었으나 원격 실행은 아직 확인하지 않았습니다.

테스트용 카탈로그를 분리하려면 다음과 같이 실행합니다.

```sh
LIGHTHOUSE_DATA_DIR="$PWD/.artifacts/test-catalog" swift run Lighthouse
```

실패(카탈로그 읽기·저장, 가져오기, 현상, 내보내기 등)는 macOS 통합 로그에 남습니다. 파일 이름과 오류 설명은 개인 정보로 표시되어 이 Mac에서 디버깅할 때만 보입니다.

```sh
/usr/bin/log stream --level info --predicate 'subsystem == "com.rian.lighthouse"'
```
