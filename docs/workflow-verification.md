## 앱 통합과 배포

- 실제 `LibraryModel`·`LibrarySession`을 연결한 독립 검사에서 플리커 적용과 undo/redo, 범위 마스크 재설정 시 ID·이름·효과 보존, 취소 후 결과 무시를 확인했다. 실제 Vision 피사체 분석을 대상별로 실행하고 원본 없는 사진은 변경 없이 실패로 보고했으며, 전체 성공분을 한 번에 실행 취소했다.
- 오프라인 편집·썸네일·전후 분할·고정 비교·여러 장 보기, 카탈로그 저장, 원본 재연결 후 전체 보정 복원을 확인했다. 노출을 바꾸면 오프라인 썸네일의 픽셀이 바뀌고 재연결 뒤에는 원본을 기준으로 썸네일을 새로 보관했다.
- 앱을 통한 전체 백업·복원·라이브러리 전환·재시작에서 파일 이름과 보정이 유지됐고 새 라이브러리 편집이 이전 카탈로그를 바꾸지 않았다. 카탈로그 없는 폴더나 손상된 사람 파일을 가진 라이브러리는 현재 라이브러리를 유지하며 열기를 거부했다.
- 실제 SwiftUI 화면을 NSWindow에 올린 검사에서 범위 슬라이더·적용, 부분 AI 선택·undo/redo, 플리커 방향 선택, 일괄 재인식 옵션, 중복 분석과 묶음 비교, 스마트 미리보기 만들기 버튼을 조작했다. AppKit 컨트롤 action과 테스트 창에 보낸 마우스 이벤트를 사용했고, 테스트 프로세스의 활성·키 창 상태를 대체했다. 오프라인 NR 선택기 비활성화와 배지를 검사했다. 밝기·색 범위, 플리커·부분 NR, 일괄 적용, 중복 결과, 스마트 미리보기, 백업·복원 화면 PNG를 확인했다. 외부 도구의 실제 release 창 조작과는 구분한다.

최초 전체 회귀에서 손상된 사람 파일이 사진 보정 저장까지 막는 회귀를 발견했다. 정상 카탈로그 저장은 손상된 보조 파일을 보존한 채 계속하고 전체 백업은 모든 저장 정보가 정상일 때만 시작하도록 수정했으며, 두 동작을 함께 확인하는 회귀 검사를 추가했다.
