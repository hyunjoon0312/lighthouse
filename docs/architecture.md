# Lighthouse 첫 버전 설계

## 확정된 사용자 요구

- macOS 전용 데스크톱 앱을 실제 실행 가능한 상태까지 만든다.
- 사진 정리, 빠른 선별, RAW 보정 세 가지를 모두 포함한다.
- Panasonic LUMIX S9의 RW2를 주 대상으로 한다.
- 로컬 우선, 원본 보존, 보정값 별도 저장을 기본으로 한다.

## 첫 버전의 완료 기준

1. 파일·폴더를 가져와 썸네일 그리드로 탐색한다. 같은 파일을 반복 가져오면 중복을 만들지 않는다.
2. 별점 0–5, 선택·제외 표시, 파일명 검색과 필터를 사용한다. 키보드로 사진을 이동·선별한다.
3. 사진을 크게 보고 100% 확대한다. 기준 사진과 현재 사진을 나란히 비교한다.
4. RW2를 실제 RAW 디코더로 읽어 노출·화이트밸런스·색감·명암·선명도를 조절한다. 원본 보기와 초기화, 회전·중앙 비율 크롭을 제공한다.
5. 보정값·분류가 앱 재시작 후 복원된다. 원본 파일을 수정하지 않는다.
6. 선택 사진 또는 필터 결과를 보정한 JPEG로 내보낸다. 크기·품질을 선택하며 기존 파일은 덮어쓰지 않는다.
7. 손상·미지원 이미지와 누락된 원본을 명시적으로 알리고 다른 사진 작업을 계속할 수 있다.

클라우드 동기화, 생성형 제거, 파노라마·HDR 병합, 카메라별 자체 색 프로파일, Lightroom 카탈로그 호환은 범위에 포함하지 않는다. 자동 마스킹과 자유 크롭 등 승인된 확장은 아래 고급 보정 계약을 따른다.

## 기술 구조

- Swift 6 도구 체인, Swift 5 언어 모드, macOS 15 이상. Swift Package Manager로 외부 의존성 없이 빌드한다.
- SwiftUI 화면과 AppKit 파일 선택·메뉴·키보드 이벤트를 사용한다.
- `LighthouseCore`: Codable 모델, 원자적 JSON 카탈로그 저장, Image I/O 메타데이터·썸네일, Core Image RAW 현상과 JPEG 출력.
- `Lighthouse` 실행 타깃: 메인 액터의 화면 상태와 저장·렌더 작업 조율. 무거운 파일 읽기와 렌더는 백그라운드에서 실행한다.
- 첫 버전 카탈로그는 `Application Support/Lighthouse/catalog.json`에 저장한다. 작은 개인 라이브러리용 단일 JSON이며 대규모 수만 장 성능은 보장하지 않는다. 향후 측정에 따라 SQLite로 이전한다.
- `LIGHTHOUSE_DATA_DIR` 환경 변수로 테스트 데이터를 격리한다. 소스 사진은 원래 위치에 두고 경로를 참조한다.
- 카탈로그 로드 오류를 빈 라이브러리로 간주해 덮어쓰지 않는다. 저장 실패는 사용자에게 표시한다.
- 보정 파라미터와 스키마 버전을 저장하고, 메모리 렌더 결과는 제한된 캐시에 둔다. 취소되거나 오래된 렌더 결과는 현재 선택 화면에 적용하지 않는다.

## 이미지 처리 계약

- RAW 파일은 `CIRAWFilter(imageURL:)`를 사용한다. 내장 JPEG를 최종 보정 원본으로 사용하지 않는다.
- 원본의 RAW 중립 색온도·틴트를 기준으로 상대 화이트밸런스 조절값을 적용한다. 기본값에서 촬영 시 화이트밸런스를 보존한다.
- 빠른 썸네일은 Image I/O를 사용할 수 있다. 편집 미리보기는 RAW 현상 후 화면 크기로 축소하고, 100% 보기는 원본 해상도로 요청한다.
- 최종 출력은 전체 해상도의 같은 보정 파이프라인을 사용하고 sRGB JPEG로 인코딩한다. 출력 시 필요하면 지정 긴 변으로 축소한다.
- `CIContext`를 재사용하고, 변경 가능한 `CIFilter` 인스턴스를 작업 사이에 공유하지 않는다. 색 관리를 유지한다.
- 90도 회전·수평 보정 후 안전 캔버스 안에서 자유 크롭을 적용한다. 이전 중앙 비율 크롭도 호환한다. 이미지와 마스크·복제 브러시가 공통 좌표 변환을 사용한다.
- 출력 파일명 충돌은 `-2`, `-3` 등의 접미사로 회피하며 원본 경로와 기존 파일을 덮어쓰지 않는다.

## 화면

어두운 중성 회색 작업 공간. 왼쪽 라이브러리·폴더·선별 필터, 가운데 그리드/큰 사진/비교, 오른쪽 보정·메타데이터 패널, 아래 필름스트립. 한국어 UI를 기본으로 한다. 처음에는 가져오기 버튼과 지원 포맷 안내를 제공하며 빈 상태에 가짜 사진·수치를 넣지 않는다.

## 검증

- 독립 임시 디렉터리에서 카탈로그 재로드, 중복 경로 처리, 오류 보존을 검증한다.
- 생성한 테스트 이미지로 보정 전후 픽셀 변화, 회전·크롭·출력 치수, 기존 파일 보존을 검증한다.
- 로컬 RAW 지원 목록에 `Panasonic LUMIX DC-S9`가 있음을 실제 조회했다 (2026-09-22, macOS 26.5.2).
- 실물 S9 RW2 파일 디코딩은 지원 목록 확인과 별개로 검증한다. 샘플을 확보하지 못하면 미검증으로 기록한다.
- 실제 앱을 실행하여 가져오기, 선택·보정, 재실행 복원, JPEG 내보내기와 화면 레이아웃을 점검한다.

## 확인한 공식 자료

- [Apple 지원 RAW 카메라 목록](https://support.apple.com/en-au/120534): LUMIX DC-S9 포함.
- [CIRAWFilter](https://developer.apple.com/documentation/coreimage/cirawfilter): RAW 센서 데이터 현상 API.
- [scaleFactor](https://developer.apple.com/documentation/coreimage/cirawfilter/scalefactor): 미리보기 축소 처리.
- [CIContext](https://developer.apple.com/documentation/coreimage/cicontext): 렌더 컨텍스트.

## 역할

Astra가 설계, 파일별 구현 계약, 최종 통합·이미지·UI 검증을 맡는다. Sol은 확정된 계약에 따라 코어와 앱 구현을 서로 다른 파일 범위에서 담당한다. 새로운 설계 판단은 Astra에게 반환한다.

## 부분 보정 확장 (2026-09-23)

사용자 요청으로 브러시·지우개 마스크와 영역별 노출·대비를 추가했다. `EditSettings.localAdjustments` 배열에 원본 기준 정규화 좌표의 스트로크를 저장한다. 이 키가 없는 기존 카탈로그는 빈 영역 배열로 읽고, 잘못된 타입이나 명시적인 null은 손상으로 처리한다.

전체 보정 뒤, 회전·크롭 전에 영역 효과를 선형 회색 마스크로 순서대로 합성한다. EXIF 방향 적용 후 원본 좌상단 좌표를 기준으로 하므로 사용자 회전·크롭 변경에도 같은 피사체에 적용된다. UI에서 칠하기는 화면 맞춤 상태로 제공하며, 최종 JPEG는 원본 해상도 마스크를 사용한다. 자세한 인터페이스와 검증 조건은 [부분 보정 계약](local-adjustments-contract.md)을 따른다.

## LUT 확장 (2026-09-23)

`EditSettings.lut`는 보관 파일의 내용 해시, 이름, 활성화 여부와 강도를 저장한다. 기존 카탈로그의 키 누락은 LUT 없음으로 복원한다. `LUTStore`는 검증한 3D `.cube`를 카탈로그 옆 `LUTs` 폴더에 보관하고 무결성을 검사한다. 카탈로그에 색상 표 전체를 중복 저장하지 않는다.

전체·부분 보정 뒤에 sRGB로 색을 변환하고 도메인 정규화와 3D 색상표 조회를 수행한 다음 Core Image 작업 공간으로 복귀한다. 강도는 LUT 전후 이미지를 작업 공간에서 합성하는 비율이다. 미리보기와 JPEG는 같은 경로를 쓰며, 원본 보기와 LUT 강도 0/비활성화는 효과를 우회한다. LUT 읽기·파싱은 UI 스레드 밖에서 처리하며 선택이 바뀐 사진에 늦게 적용하지 않는다. 범위와 인터페이스는 [LUT 계약](lut-contract.md)을 따른다.

## 보관·일괄 편집·참조 색감·폴더 확장 (2026-09-23)

- LUT 파일 옆 이름 sidecar를 보관하고 전체 목록을 조회한다. 이전 sidecar 없는 파일도 읽으며 개별 손상을 목록 오류로 격리한다. 여러 `.cube`를 한 번에 추가할 수 있다.
- `PhotoSelectionState`는 선택 집합·기준·범위 시작점을 관리한다. `EditComponents`로 보정 범위를 명시하고 `EditHistory`로 여러 사진 변경을 한 실행 취소 단위로 저장한다. 보이지 않는 사진을 대상에서 제외한다.
- `ReferenceColorMatcher`는 현재 사진의 LUT를 제외한 sRGB 렌더와 참조의 색 통계를 분석한다. CIELAB 평균·표준편차의 제한된 변환을 33³ 색상표로 만든다. 사진의 공간적 내용은 바꾸지 않는다. 생성 강도는 sRGB 변환 안에 저장하며, 이후 앱의 LUT 강도 슬라이더는 기존 선형 작업 공간 혼합을 사용한다.
- S9용 생성 파일은 full range 및 `#LUMIXPHOTOSTYLE STD`로 Standard 기반을 명시한다. V-Log 변환은 제공하지 않으며 실기 로딩·촬영은 별도 검증 대상이다.
- `PhotoFolderStore`는 `folders.json`에 폴더 이름과 사진 ID 집합을 저장한다. 실제 파일 경로와 보정 카탈로그를 변경하지 않는다. 폴더 로드 오류가 있어도 사진 보정은 계속할 수 있고, 손상된 폴더 파일은 덮어쓰지 않는다.

각 확장 계약과 사용자 안내는 README에 연결한다. 네 가지 기능도 원본 파일을 참조만 하고 결과를 별도로 저장한다.

## 고급 보정 확장 (2026-09-23)

승인한 여섯 기능의 저장·처리·화면 경계는 [고급 보정 계약](advanced-editing-contract.md)에 정의한다.

- Vision이 생성한 원본 방향의 회색 마스크를 카탈로그에 저장한다. 피사체/반전 배경 위에 수동 브러시를 더하고 지운다.
- RGB 곡선과 HSL 색상 범위는 sRGB 수치의 Float 색상표를 통해 처리한다. 필름 입자는 저장된 seed와 원본 픽셀 좌표로 재현한다.
- `PhotoGeometry`가 quarter turn·수평 안전 영역·정규화 자유 크롭의 좌표를 일원화한다. 기존 부분 보정과 복구 위치는 원본 좌표로 보존한다.
- 복제와 주변 패치 스팟 복구는 별도 stroke 배열에 저장한다. 복구는 작은 결함의 질감·밝기를 완화하는 방식이며 생성형 제거는 아니다.
- 전체 처리 순서는 기존 현상·전체 보정 → 복구 → 곡선/HSL → 부분 보정 → LUT → 입자 → 구도 → 출력 축소다. 원본 보기에서는 중립 설정을 사용한다.
- JPEG 미리보기는 실제 압축 데이터를 디코딩해 보여준다. 내보내기 시 사진·보정·출력 옵션이 정확히 같은 경우 준비된 데이터를 재사용한다.

사용 방법은 [고급 보정 안내](advanced-editing.md), 실제 검사 결과와 남은 범위는 [검증 기록](verification.md)을 따른다.
