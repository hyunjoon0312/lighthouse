v1 검사에는 “누락 입력은 init 단계에서 거부된다”는 잘못된 기대가 있었다. 공통 런타임은 누락을 `missing` 지문으로 표현하므로 기대를 실제 API에 맞게 수정했다. 개발 조율 스킬에는 메인이 init/resume와 배정 전에 필수 입력의 존재·읽기 가능 여부를 확인하도록 추가했다. 필수 실패와 누락 결과가 소비자 실행·완료를 차단하는 검사는 유지했다. 설치된 런타임 소스는 변경하지 않았다.

현재 협업 도구는 커스텀 역할 선택 인자를 제공하지 않아 역할 지시를 명시적으로 전달하고 spawn에 모델·effort를 지정했다. 이 실행은 TOML 역할 자동 선택이나 역할별 OS 샌드박스 강제를 검증한 것은 아니다. 새 세션의 스킬 자동 선택률도 측정하지 않았다. 저장소의 역할 정의와 실제 도구 호출·행동 검증을 구분한다.

하네스 변경 범위에 맞춰 앱 전체 빌드·화면·S9 실기 검사는 재실행하지 않았다. 기존 앱 기능의 검증 범위와 미검증 사항은 [앱 검증 기록](verification.md)을 따른다.

원시 근거는 로컬 `.artifacts/harness-setup/`, `.harness/runs/`, `_workspace/communications/`에 보관한다. 이 경로들은 Git에서 제외되며 다른 PC에는 자동 복원되지 않는다. 저장소에 포함한 회귀 검사와 [개발 하네스 안내](harness.md)로 다시 검증할 수 있다.
