# 텍스처·디헤이즈·화이트밸런스 계약 v1

2026-10-09 사용자 요청("나머지도 다 구현해줘")에 따른 두 번째 하위 프로젝트다. 앱에서 텍스처·디헤이즈를 조절하고, RAW의 화이트밸런스를 Lightroom처럼 기준값(촬영 시·주광·흐림 등)으로 고를 수 있게 한다. Lightroom 프리셋의 해당 키도 가져온다. 성공 기준은 [컬러 그레이딩](color-grading-contract.md)과 같다: 같은 값이 같은 방향·역할로 움직인다. Adobe 현상 엔진과 같은 픽셀은 보장하지 않는다. 기존 보정과 값이 0일 때의 출력은 그대로다.

사용자가 설계 승인 단계를 생략하고 구현을 맡겼으므로, 아래 결정은 이 세션의 Claude가 내렸다.

## 모델과 저장

- `EditSettings.texture`, `EditSettings.dehaze`: -1…1, 기본 0. 키가 없으면 0이다. 비유한 값·범위 밖 값은 디코드 오류다. 0이면 키를 쓰지 않아 기존 카탈로그와 썸네일 키가 그대로다.
- `EditSettings.whiteBalance: WhiteBalanceBase?`: RAW 화이트밸런스 기준값. nil은 "촬영 시"다. `temperature` 2000…50000 K, `tint` -150…150. 범위 밖이면 디코드 오류이고, nil이면 키를 쓰지 않는다.
- 기존 `temperatureShift`·`tintShift`는 기준값 위에 더하는 이동량으로 남는다. 회색 찍기·자동 보정도 기준값 위의 이동량을 정한다.
- `WhiteBalancePreset`: 촬영 시(nil), 주광 5500/+10, 흐림 6500/+10, 그늘 7500/+10, 텅스텐 2850/0, 형광등 3800/+21, 플래시 5500/0. 값은 Lightroom 기본 목록의 근삿값이다.
- `.global` 일괄 복사에 셋 다 포함한다. 변경 이름은 "텍스처", "디헤이즈", "화이트밸런스"다. 부분 보정에는 넣지 않는다.

## 렌더

- **화이트밸런스(RAW만):** 기준값이 있으면 `neutralTemperature = clamp(기준 K + 색온도 이동, 2000, 50000)`, `neutralTint = clamp(기준 틴트 + 틴트 이동, -150, 150)`. 없으면 지금처럼 촬영 시 값에 이동량을 더한다. RAW가 아닌 파일은 기준값을 무시한다(Lightroom도 JPEG에는 켈빈 값을 쓰지 않는다). 현상 캐시·노이즈 감소 캐시 키에 기준값을 넣는다. 기준값이 바뀌면 근사 없이 다시 현상한다.
  - Core Image의 켈빈은 Adobe 켈빈과 같은 척도라고 가정한다(근사).
  - 스마트 미리보기(원본 없이 보는 JPEG 대리본)에서는 기준값이 반영되지 않는다. 알려진 한계다.
- **디헤이즈:** 현상 단계에서 노출·색온도 다음, 흑백 변환 앞에 둔다. 선형 작업 공간 값으로 계산한다.
  - 어두운 채널 `d`: 짧은 변 512px 이하로 줄인 이미지에서 픽셀의 `min(R,G,B)`(0…1로 자름) → 짧은 변 0.4% 반경 최솟값 필터 → 1% 반경 가우시안 블러 → 원래 크기로 선형 확대. 처음에는 원래 크기에서 구했으나 1600px에서 1.8초가 걸려 줄였다.
  - 양수 a: 대기광을 흰색(1)으로 보고 `t = max(0.3, 1 - 0.7·a·d)`, `J = (I - 1) / t + 1`. 검정과 흰색은 그대로이고, 뿌연 밝은 곳일수록 어두워지며 채도가 오른다.
  - 음수 a: `J = mix(I, 0.6, -0.25·a)`로 회색 안개를 씌운다. 처음 값 `mix(I, 0.7, -0.5·a)`는 S9 표본에서 -60만으로도 검정이 회색이 될 만큼 강했다.
  - 0…1 안에서 계산하고 0…1 밖의 초과분은 그대로 더해 확장 범위를 보존한다. 어두운 채널을 같은 크기에서 구하므로 미리보기와 내보내기가 같은 모양이다.
- **텍스처:** 명료도 바로 뒤에 둔다. 명료도와 같은 중간 톤 가중 대비 커널을 쓰되, 반경을 짧은 변의 0.04%(fine)·0.4%(coarse)로, 강도를 `0.8·a`로 한다. 양수는 잔 디테일을 키우고 음수는 부드럽게 한다.
- 값이 0이면 필터를 건너뛰어 기존 출력과 픽셀이 같다.

## 앱

- 톤 섹션: 검정 다음에 텍스처, 명료도(기존), 디헤이즈 순서. 범위 -100…100, 두 번 누르면 0.
- 색상 섹션: RAW 사진에만 "화이트밸런스" 메뉴를 보인다. 고르면 기준값을 바꾸고 색온도·틴트 이동을 0으로 둔다(Lightroom처럼 고른 값에서 다시 시작). 목록에 없는 기준값(프리셋에서 가져온 값)은 "사용자 지정 (5200 K, +8)"으로 보인다. 한 번 고르기가 실행 취소 1단계다.
- 일괄 복사 시트의 "전체 보정" 설명에 텍스처·디헤이즈·화이트밸런스를 더한다.

## 프리셋 가져오기

| 키 | 범위 | 적용 |
|---|---|---|
| `Texture`, `Dehaze` | -100…100 | ÷100 |
| `Temperature` / `Tint` | 2000…50000 / -150…150 | RAW 기준값 |
| `IncrementalTemperature` / `IncrementalTint` | -100…100 | JPEG 등: 색온도 이동 ×25 K / 틴트 이동 그대로 |
| `WhiteBalance` | 문자열 | 아래 규칙 |

- `WhiteBalance`: As Shot, Auto, Custom, Daylight, Cloudy, Shade, Tungsten, Fluorescent, Flash(대소문자 무시). 다른 값은 "지원하지 않아 제외" 경고를 낸다. 서로 다른 값이 반복되면 기존 규칙대로 오류다.
- 적용은 사진마다 RAW 여부를 받아 정한다(`applied(to:isRAW:)`).
  - RAW: As Shot이면 기준값 nil·이동 0. `Temperature`가 있으면(As Shot·Auto가 아닐 때) 기준값 `(Temperature, Tint ?? 0)`·이동 0. 이름 있는 값(Daylight 등)에 `Temperature`가 없으면 `WhiteBalancePreset` 값을 쓴다. `Incremental*`은 무시한다.
  - RAW가 아님: As Shot이면 이동 0. 그 뒤 `IncrementalTemperature`·`IncrementalTint`가 있으면 이동량을 덮어쓴다(색온도는 -2500…2500 K로 자른다). 켈빈 값은 무시한다.
  - Auto는 적용하지 않고 "자동 화이트밸런스는 적용하지 않습니다." 경고를 낸다.
- 화이트밸런스 키가 하나라도 있으면 "화이트밸런스는 macOS RAW 현상의 색온도로 근사하며 Adobe 결과와 다를 수 있습니다." 경고를 더한다.
- payload에 `whiteBalance: String?`을 더한다. 없으면 키를 쓰지 않아 기존 payload가 그대로 읽힌다.

## 검증

- 모델: 기본값·키 생략·roundtrip·범위 오류, 일괄 복사·변경 이름.
- 렌더: 0이면 무변화, 디헤이즈 양수는 안개 낀 회색 위 색의 채도·대비를 올리고 검정·흰색을 유지, 음수는 대비를 낮춤, 텍스처 양수는 잔 무늬의 진폭을 키우고 음수는 줄임, 미리보기와 내보내기 일치. RAW 중립값 계산(기준값·이동·자르기)은 순수 함수로 확인한다.
- 가져오기: 키별 범위, RAW/JPEG 적용 차이, As Shot·Auto·이름 있는 값, 경고, 부분 적용 시 나머지 유지.
- 앱: 화이트밸런스 고르기 1단계 실행 취소, 프리셋 적용 시 RAW·JPEG 차이.
- 실제 S9 RW2로 주광·텅스텐 기준값, 디헤이즈 ±, 텍스처 ±를 렌더해 방향을 보고 원본 SHA가 같은지 확인한다.
